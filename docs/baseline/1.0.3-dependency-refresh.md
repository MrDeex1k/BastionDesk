# BastionDesk 1.0.3 — odświeżenie zależności baseline'u

## Zakres

Przed końcowymi pomiarami fazy 0 odświeżono zależności aplikacyjne i obrazy
runtime do najnowszych stabilnych wersji dostępnych 4 września 2026. Pomiary
kroku 5 dotyczą więc baseline'u `1.0.3` wraz z poprawkami fazy 0 i tym
checkpointem zależności, a nie samego historycznego tagu `v1.0.3`.

## Zmiany

- Bun i obrazy build/runtime: `1.4.0` → `1.4.1`.
- NGINX w proxy i frontendzie: `1.31.4-alpine3.24` →
  `1.31.5-alpine3.24`.
- uv w builderze i runtime LLM: `0.12.7` → `0.12.9`.
- `conventional-changelog-conventionalcommits`: `8.0.0` → `10.4.0`.
- Lockfile Bun odświeżono przez `bun update --latest`; wszystkie bezpośrednie
  zależności workspace'ów pozostały na najnowszych dostępnych wersjach, a
  rozwiązania przechodnie zostały zaktualizowane w granicach ich kontraktów.
- Lockfile uv odświeżono przez `uv lock --upgrade`. Zaktualizowano `anyio`,
  `cuda-pathfinder`, `filelock`, `protobuf`, `pydantic`, `pydantic-core` i
  `regex`; wersje bezpośrednie z `pyproject.toml` pozostały aktualne.

Pozostałe przypięte obrazy były już najnowszymi stabilnymi wydaniami w swoich
liniach: PostgreSQL `18.6`, PgBouncer `1.25.2-p0`, BusyBox `1.38.0-musl`,
MinIO `RELEASE.2025-10-15T17-29-55Z` i MinIO Client
`RELEASE.2025-08-13T08-35-41Z`.

## Weryfikacja

Po odświeżeniu wykonano:

- `bun outdated --latest` — brak zaległych aktualizacji;
- `uv lock --project llm_service --upgrade --dry-run` — brak zmian lockfile'a;
- `bun run check` — lint, typecheck i format dla obu workspace'ów;
- pełny zestaw testów backendu — 30 testów zaliczonych;
- import i zbudowanie konfiguracji presetu changeloga po aktualizacji major;
- `docker compose build --pull` — wszystkie obrazy zbudowane z odświeżonych
  baz;
- `bun run test:baseline:smoke` — wszystkie usługi zdrowe oraz kontrakty API,
  auth i CSRF zaliczone;
- `bun run test:baseline:restore` — dump odtworzony z zachowaniem liczności,
  relacji tenantów i semantyki healthchecku.

Historyczny dokument wydania `v1.0.3` zachowuje wersje użyte w tagu. Bieżącym
źródłem prawdy dla pomiarów fazy 0 jest ten checkpoint i Dockerfile'e na
branchu `chore/phase-0-baseline`.

## Aktualizacja main — 10 listopada 2026

Odświeżono bezpośrednie zależności NPM w katalogu głównym, obu workspace'ach
i prototypie Elysia oraz zależności przechodnie w lockfile'ach. Zachowano
minimalny wiek wydania 24 godziny skonfigurowany dla Bun i uv. Elysia pozostaje
na linii prerelease 2.x (`2.0.0-rc.4`). Aktualizacja do Effect `4.1.2` wymagała
przejścia z `Context.Tag` na `Context.Service`, z `Either` na `Result` oraz
z `timeoutFail` na `timeoutOrElse`, z zachowaniem dotychczasowego błędu domenowego.
OpenTelemetry `0.301.1` wymaga bezpośredniego importu czytnika metryk
z `@opentelemetry/sdk-metrics` zamiast eksportu z `sdk-node`.

Python: FastAPI `0.162.2`, grpcio i grpcio-tools `1.85.1`, huggingface-hub
`2.4.0`, torch `2.15.0`, transformers `5.22.2`, uvicorn `0.54.0`.
FastAPI `0.162.3` pominięto, ponieważ nie spełniało limitu wieku wydania.
Zachowano Python 3.13 i osobny indeks CPU dla PyTorch.

Obrazy: Bun `1.4.4-alpine`, NGINX `1.31.8-alpine3.24`, uv
`0.13.7-python3.13-trixie-slim`, RabbitMQ `4.4.0-management-alpine`,
PgBouncer `v1.26.1-p0`, OpenTelemetry Collector `0.165.0` i Mailpit `v1.33.1`.
Referencja RabbitMQ w skrypcie discovery odpowiada Compose. PostgreSQL `18.6`,
BusyBox `1.38.0-musl` oraz przypięte wydania MinIO i mc były już aktualne.
Przed aktualizacją istniejącego RabbitMQ trzeba włączyć stabilne feature flags
zgodnie z [instrukcją producenta](https://www.rabbitmq.com/docs/upgrade).

Weryfikacja tej aktualizacji obejmuje build i lint frontendu, kontrolę typów
oraz build trzech punktów wejścia backendu, lint Pythona, instalację zależności
z `uv.lock` w tymczasowym środowisku, kompilację Pythona i generowanie gRPC.
Nie uruchamiano zestawów testów, modelu LLM ani stosu Docker Compose.
Tagi obrazów sprawdzono w rejestrach; buildy obrazów pozostają niezweryfikowane,
ponieważ lokalny silnik Docker nie był dostępny (`docker.sock` nie istnieje).
