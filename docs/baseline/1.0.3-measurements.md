# BastionDesk 1.0.3 — pomiary i ocena zamknięcia baseline'u

## Punkt pomiarowy

Pomiary wykonano 4 września 2026 na branchu `chore/phase-0-baseline`, po
commicie odświeżającym zależności `5da4a7f`. Jest to wersja aplikacji `1.0.3`
wraz z poprawkami fazy 0, a nie niezmieniony historyczny tag `v1.0.3`.

Środowisko pomiarowe:

- MacBook Pro z Apple M4 Pro, 12 rdzeniami i 24 GB RAM;
- OrbStack z Docker Engine `29.4.0`, 12 CPU i 11,73 GiB RAM dla maszyny
  `linux/arm64`;
- 11 usług Compose i zachowane lokalne wolumeny;
- obrazy przebudowane przez `docker compose build --pull`.

Powtarzalny pomiar uruchamia:

```bash
bun run test:baseline:measure
```

Skrypt zatrzymuje kontenery bez usuwania wolumenów, mierzy ponowny start do
stanu healthy, wykonuje po 30 sekwencyjnych żądań do lekkich endpointów,
następnie pobiera pojedynczą próbkę `docker stats` i logiczne rozmiary obrazów.

## Końcowa weryfikacja

Po aktualizacji zależności i przed oceną zamknięcia zaliczono:

- brak zaległych aktualizacji według `bun outdated --latest` i
  `uv lock --upgrade --dry-run`;
- `bun run check`;
- 30/30 testów w `bun run test:baseline`;
- pełny `docker compose build --pull`;
- smoke wszystkich 11 usług, publiczne granice API/auth/CSRF i wewnętrzny
  health backendu;
- cztery poprawne przebiegi backup/restore łącznie, w tym przebieg po
  aktualizacji zależności i przebieg czasowy z kroku 5.

## Decyzja zamknięcia

**Baseline jest zamrożony jako mierzalny punkt techniczny, ale kryterium
ukończenia fazy 0 nie jest jeszcze spełnione. Decyzja dla rozpoczęcia fazy 1:
NO-GO.**

Macierz definiuje 41 scenariuszy `P0` i mówi, że pominięcie któregokolwiek jest
niezaliczeniem. Obecna automatyzacja świadomie nie jest wykonaniem wszystkich
58 scenariuszy: pokrywa kontrakty, wybrane granice tenantów, walidację uploadu,
smoke oraz `OPS-01-*`, lecz nie zapisuje wyniku pełnych przepływów `A3`.
Brakuje przede wszystkim wykonywalnego fixture sesji i kompletnej regresji:

- rejestracji, weryfikacji emaila, logowania, wylogowania i resetu hasła z
  kontrolowanym SMTP;
- zarządzania członkami i rolami przez rzeczywiste API;
- pełnego cyklu incydentu przez API, wraz z MinIO, audytem i pobraniem plików;
- tenant scope wszystkich list, mutacji i agregatów na danych dwóch
  organizacji;
- klasyfikacji wpiętej w utworzenie incydentu, a nie tylko kontraktu klienta
  gRPC;
- ponownego uruchomienia API nad odtworzoną bazą i testu sesji/loginu z
  `OPS-01-03`.

Następnym krokiem fazy 0 jest zatem domknięcie i wykonanie pakietu `P0 A3`, z
raportem per ID scenariusza. Alternatywą jest jawna zmiana kryterium oraz
priorytetów macierzy w osobnej decyzji projektowej; nie należy uznawać
częściowej automatyzacji za pełne zaliczenie bez takiej decyzji.

## Ograniczenia porównania

- Wyniki zależą od hosta, przydziału zasobów i rozgrzanych wolumenów.
- Start nie obejmuje pobierania ani budowania obrazów.
- Pomiary HTTP są sekwencyjne i nie obejmują zalogowanego workflow.
- Próbka zasobów nie zastępuje profilu pod obciążeniem ani dłuższej obserwacji.
- Rozmiar LLM zawiera zależności CUDA także w obrazie `arm64`; to pierwszy
  kandydat do optymalizacji obrazu, ale nie blokuje zamrożenia baseline'u.
