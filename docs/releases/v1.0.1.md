# BastionDesk v1.0.1

A patch release focused on security hardening, consolidating the supported Docker Compose
deployment, and improving filter stability and runtime behavior.

BastionDesk `1.0.1` does not change the product scope of the `1.0.x` line. It strengthens the
default self-hosted path around a single public entry point, safer application requests,
improved browser protections, and more predictable error handling across the backend, frontend,
and local LLM service.

## Included

- Standardized public application access through `http://localhost:4567`.
- Backend, PostgreSQL, PgBouncer, MinIO, and `llm_service` are no longer published directly on
  the host by default in the supported Compose path.
- Added CSRF protection for state-changing application endpoints.
- Added frontend CSRF token bootstrap, token refresh, and retry handling for expired tokens.
- Added stricter validation for `FRONTEND_URL`, `BETTER_AUTH_URL`, the WebAuthn origin, CORS
  origins, and Better Auth trusted origins.
- Added `CSRF_SECRET` to the environment configuration.
- Added browser security headers to the public and frontend nginx instances.
- Removed public `/llm/` routing from the reverse proxy.
- Improved LLM error mapping for timeout, unavailable, invalid request, and invalid response
  conditions.
- `llm_service` now reports explicit `ok` or `degraded` status and returns HTTP `503` when the
  model has not loaded successfully.
- Migrated parameterized SQL helper queries from unsafe `Bun.SQL.unsafe` execution to the `pg`
  Pool.
- Standardized administrator and analyst incident sorting with explicit SQL column allowlists.
- Improved administrator incident filtering: analyst options are loaded dynamically from the
  API, while user search supports ID, name, and email.
- Added lazy loading for heavier dashboard sections, incident details, settings, and reporting
  forms.
- Added `VITE_API_TIMEOUT_MS` and more predictable frontend timeout and network-error handling.
- Added optional outbound proxy support for `llm_service`, allowing Hugging Face model downloads
  in environments without direct internet access.
- Updated API, proxy, and deployment documentation for the current single-entry-point model.

## Security

- CSRF protection covers state-changing requests under `/api/incidents`, `/api/admin`, and
  `/api/analyst`.
- CSRF tokens are issued by `GET /api/csrf`, bound to the active session or an anonymous seed,
  and sent through `X-CSRF-Token`.
- The default frontend model now uses same-origin access through the reverse proxy without a
  separate `VITE_API_URL`.
- In production mode, application startup rejects a weak `CSRF_SECRET` and non-HTTPS origins for
  `FRONTEND_URL`, `BETTER_AUTH_URL`, `WEBAUTHN_ORIGIN`, `CORS_ORIGIN`, and
  `BETTER_AUTH_TRUSTED_ORIGINS`.
- The edge and frontend nginx layers hide `server_tokens` and set protective headers, including
  CSP, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, and
  `Permissions-Policy`.
- The supported Compose path no longer publishes the backend, database, PgBouncer, MinIO, or
  `llm_service` directly.

## Deployment Notes

- Supported `1.0.1` release model: self-hosted Docker Compose.
- The deployment model remains `fresh install only`.
- The only public application entry point remains:
  - `http://localhost:4567`
- The default local deployment assumes:
  - `BETTER_AUTH_URL=http://localhost:4567`
  - `BETTER_AUTH_TRUSTED_ORIGINS=http://localhost:4567`
  - `VITE_API_URL` is empty or unset
- Environments requiring outbound proxy access can set:
  - `HTTP_PROXY`
  - `HTTPS_PROXY`
  - `NO_PROXY`

## Known Notes

- `1.0.1` remains within the `fresh install only` model.
- In the default Compose configuration, internal services are not directly accessible from the
  host. Debugging requires `docker compose exec`, temporarily publishing ports, or entering the
  Docker network.
- `llm_service` may still have a noticeable cold start and memory requirements while loading the
  model.
- Environments without direct internet access require correct `llm_service` proxy configuration
  to download the model.
