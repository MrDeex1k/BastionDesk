# BastionDesk v1.0.1

Patch release skoncentrowany na hardeningu bezpieczeństwa, uporządkowaniu wspieranego deploymentu Docker Compose oraz poprawie stabilności filtrów i zachowania runtime.

BastionDesk `1.0.1` nie zmienia zakresu produktu z linii `1.0.x`, ale wzmacnia domyślną ścieżkę self-hosted wokół jednego publicznego entrypointu, bezpieczniejszych requestów aplikacyjnych, lepszej ochrony przeglądarkowej i bardziej przewidywalnej obsługi błędów po stronie backendu, frontendu oraz lokalnego serwisu LLM.

## Included

- Publiczny dostęp do aplikacji został ujednolicony wokół `http://localhost:4567`.
- Backend, PostgreSQL, PgBouncer, MinIO i `llm_service` nie są już domyślnie publikowane bezpośrednio na hoście w wspieranej ścieżce Compose.
- Dodano ochronę CSRF dla mutujących endpointów aplikacyjnych.
- Dodano frontendowy bootstrap tokenu CSRF, odświeżanie tokenu i retry dla wygasłych tokenów.
- Dodano ściślejszą walidację `FRONTEND_URL`, `BETTER_AUTH_URL`, originu WebAuthn, originów CORS i trusted origins Better Auth.
- Dodano `CSRF_SECRET` do konfiguracji środowiskowej.
- Dodano browser security headers w publicznym `nginx` oraz frontendowym `nginx`.
- Usunięto publiczny routing `/llm/` z reverse proxy.
- Usprawniono mapowanie błędów LLM na timeout, unavailable, invalid request i invalid response.
- `llm_service` zwraca teraz jawny status `ok` / `degraded` oraz HTTP `503`, jeśli model nie został poprawnie załadowany.
- Pomocnicze zapytania SQL z parametrami przeszły z niebezpiecznego wykonania przez `Bun.SQL.unsafe` na `pg` Pool.
- Uporządkowano sortowanie incydentów admina i analityka przez jawne allowlisty kolumn SQL.
- Poprawiono filtrowanie incydentów administratora: lista analityków jest pobierana dynamicznie z API, a wyszukiwanie użytkownika działa po ID, nazwie i emailu.
- Dodano lazy loading cięższych sekcji dashboardów, szczegółów incydentu, ustawień i formularzy zgłoszeń.
- Dodano `VITE_API_TIMEOUT_MS` oraz bardziej przewidywalną obsługę timeoutów i błędów sieciowych po stronie frontendu.
- Dodano opcjonalne outbound proxy dla `llm_service`, aby model mógł zostać pobrany z Hugging Face również w środowiskach bez bezpośredniego dostępu do internetu.
- Zaktualizowano dokumentację API, proxy i deploymentu pod aktualny model single-entrypoint.

## Security

- Ochrona CSRF obejmuje mutujące requesty pod `/api/incidents`, `/api/admin` i `/api/analyst`.
- Token CSRF jest wydawany przez `GET /api/csrf`, wiązany z aktywną sesją lub anonimowym seedem i przekazywany przez `X-CSRF-Token`.
- Domyślny model frontendu opiera się teraz na same-origin przez reverse proxy, bez potrzeby osobnego `VITE_API_URL`.
- W trybie produkcyjnym start aplikacji odrzuca słaby `CSRF_SECRET` i nie-HTTPS origins dla `FRONTEND_URL`, `BETTER_AUTH_URL`, `WEBAUTHN_ORIGIN`, `CORS_ORIGIN` i `BETTER_AUTH_TRUSTED_ORIGINS`.
- Warstwa edge i frontend `nginx` ukrywają `server_tokens` i ustawiają nagłówki ochronne, w tym CSP, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy` i `Permissions-Policy`.
- Wspierana ścieżka Compose nie publikuje już bezpośrednio backendu, bazy, PgBouncera, MinIO i `llm_service`.

## Deployment Notes

- Wspierany model wydania `1.0.1`: self-hosted Docker Compose.
- Model wdrożenia pozostaje `fresh install only`.
- Jedynym publicznym entrypointem aplikacji pozostaje:
  - `http://localhost:4567`
- Domyślny lokalny model uruchomienia zakłada:
  - `BETTER_AUTH_URL=http://localhost:4567`
  - `BETTER_AUTH_TRUSTED_ORIGINS=http://localhost:4567`
  - `VITE_API_URL` pozostawione puste lub nieustawione
- Środowiska wymagające wyjścia przez proxy mogą ustawić:
  - `HTTP_PROXY`
  - `HTTPS_PROXY`
  - `NO_PROXY`

## Known Notes

- `1.0.1` pozostaje w modelu `fresh install only`.
- W domyślnej konfiguracji Compose usługi wewnętrzne nie są bezpośrednio dostępne z hosta; debugowanie wymaga `docker compose exec`, tymczasowego wystawienia portów lub wejścia do sieci Docker.
- `llm_service` nadal może mieć zauważalny cold start i wymagania pamięciowe podczas ładowania modelu.
- Jeśli środowisko nie ma bezpośredniego dostępu do internetu, pobranie modelu wymaga poprawnej konfiguracji proxy dla `llm_service`.
