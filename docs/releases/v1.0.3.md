# BastionDesk v1.0.3

Release `1.0.3` modernizes the frontend foundation, adds validated administrative `QUERY` APIs,
strengthens secure dependency management, and completes fixes discovered during end-to-end
application validation. Public routes, roles, the data model, and the supported Docker Compose
deployment remain compatible with the `1.0.x` line.

## Highlights

### TanStack Router

- Replaced React Router with TanStack Router.
- Routing now uses a typed, file-generated route tree, validated search parameters, and
  `beforeLoad` guards for sessions, organizations, and roles.
- Navigation, redirects, and browser history preserve the existing application URLs.
- Automatic route-level code splitting keeps dashboards and heavier views out of the initial
  bundle.
- Password reset requests without a token are handled before rendering and redirect to the login
  view with a typed message.

### shadcn/ui on Base UI

- Migrated every local Radix wrapper to shadcn/ui components based on `@base-ui/react`.
- Removed eight direct `@radix-ui/react-*` dependencies; neither the source tree nor the lockfile
  contains Radix packages.
- The migration covers Button, Badge, Label, Scroll Area, Tabs, Dialog, Dropdown Menu, Select,
  and Alert Dialog.
- Preserved controlled and uncontrolled values, forms, focus handling, portals, scroll locking,
  keyboard support, and mobile popup positioning.
- The organization-member deletion alert remains open until the mutation succeeds, prevents
  duplicate requests, and keeps errors visible for retry.

### Typography and Icons

- The complete interface now uses the locally hosted Geist Mono `1.7.0` variable font.
- The WOFF2 file and SIL Open Font License are stored in the repository; the browser does not
  retrieve the font from an external CDN.
- Lucide remains the only standard UI icon library. Font Awesome was not added.

### Administrative QUERY APIs

- Added `QUERY /api/admin/incidents` with strict JSON validation, paginated filtering, searching,
  allowlisted sorting and a maximum page number of `1000`.
- Added `QUERY /api/admin/analytics/metrics` with relative or absolute date ranges, validated IANA
  timezones, grouping, filters and selectable metric sets.
- Kept the previous `GET` contracts as validated adapters until 14 February 2027, with deprecation,
  sunset, migration-link and `Accept-Query` response headers.
- Added `QUERY` to CORS and CSRF-safe method handling; unsupported methods and media types receive
  explicit responses.
- Added schema and execution regression tests covering PostgreSQL aggregate normalization,
  pagination scope, date-range consistency and validation boundaries.

## Dependency Security

- Socket Firewall (`sfw`) is a root workspace development dependency.
- The root `deps:install` and `deps:update` scripts run Bun through SFW, which filters
  package-manager traffic during dependency installation and updates.
- The repository uses one canonical root `bun.lock`; Docker builds install filtered workspaces
  from that lockfile and no longer maintain child lockfiles.
- Reduced the Bun package release-age quarantine from 48 to 24 hours (`86400` seconds).
- Aligned the `uv` release-age quarantine for the LLM service with Bun at 24 hours.
- Updated all JavaScript, TypeScript, and Python dependencies eligible under that quarantine;
  direct dependencies retain exact version pins.

Use the following commands for local dependency management:

```bash
bun run deps:install
bun run deps:update
bun install --cwd frontend --frozen-lockfile
bun install --cwd backend --frozen-lockfile
bun run changelog:generate
```

Direct `bun install` and `bun update` commands retain the quarantine configured in the root and
workspace `bunfig.toml` files, but bypass SFW. Dependency installation performed while building
Docker images also does not currently pass through SFW. Bun is not listed among the package
managers officially supported by Socket Firewall Free, although the integration works in this
project.

## Fixes

- Fixed `GET /api/admin/incidents/filters` by removing an unnecessary `SELECT DISTINCT` that
  conflicted with its PostgreSQL `ORDER BY` expression and caused HTTP `500` responses.
- Password reset requests without a `token` no longer render an invalid form.
- Selects retain labels, role icons, business values, filter reset behavior, and form-field
  serialization after the primitive-library migration.
- Login, passkey login, registration and organization creation now await auth-cache and router
  synchronization; failed synchronization leaves an actionable warning and reload fallback.

## Performance

- Replaced broad `transition-all` declarations with explicit transition-property lists. React
  Doctor still reports two `animate-in` false positives, but no `transition-all` remains in
  `frontend/src`.
- Kept Recharts in a separate lazy-loaded production chunk.

## Infrastructure

- Updated the Bun runtime to `oven/bun:1.4.0-alpine` and the public proxy and frontend runtime
  images to `nginx:1.31.4-alpine3.24`.
- Updated the database image to `postgres:18.6` and the backup runtime to
  `postgres:18.6-alpine3.24`.
- Updated the LLM service builder and runtime images to
  `ghcr.io/astral-sh/uv:0.12.7-python3.13-trixie-slim`.

## Versions and Compatibility

- The frontend, backend, LLM service, and API metadata use version `1.0.3`.
- The supported deployment model remains self-hosted Docker Compose.
- The main entry point remains `http://localhost:4567`.
- The deployment model remains `fresh install only`; this release does not provide an official
  procedure for upgrading existing volumes.
- The administrative API was extended with QUERY endpoints while existing GET contracts remain
  compatible during the announced deprecation window.
- No database schema migration is required.
