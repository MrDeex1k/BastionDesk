# BastionDesk v1.0.2

Wydanie utrzymaniowe skoncentrowane na modernizacji narzędzi programistycznych, przewidywalnym rozwiązywaniu zależności oraz odświeżeniu bazowych obrazów kontenerów używanych przez wspierany deployment Docker Compose.

BastionDesk `1.0.2` nie zmienia zakresu funkcjonalnego linii `1.0.x`. Aktualizacja porządkuje sposób lintowania, formatowania i kompilowania kodu TypeScript, przypina dokładne wersje pakietów oraz aktualizuje wybrane obrazy runtime bez zamierzonej zmiany API, schematu bazy danych lub zachowania użytkowego aplikacji.

## Developer Tooling

- Frontend przeszedł z ESLint na type-aware OxLint.
- Backend przeszedł z kontroli Biome na type-aware OxLint.
- OxFmt jest wspólnym formatterem kodu TypeScript i TSX, z osobną konfiguracją dopasowaną do frontendu i backendu.
- Frontend i backend używają TypeScript `7.0.2`.
- Target i biblioteki ECMAScript frontendu zostały ustawione na `ESNext` zamiast `ES2025`.
- Istniejące źródła TypeScript i TSX zostały ujednolicone zgodnie z konfiguracją OxFmt.
- README wskazuje Oxc jako aktualny zestaw narzędzi lintowania i formatowania.

## Dependencies

- Zaktualizowano zależności frontendu i backendu oraz odpowiadające im lockfile Bun.
- Wszystkie bezpośrednie wersje w manifestach Bun zostały przypięte dokładnie, bez zakresów `^` i `~`.
- Karencja dla nowych wydań pakietów Bun została skrócona z 60 do 48 godzin (`172800` sekund).
- Skrypty instalowania i aktualizowania zależności zachowują tę samą 48-godzinną karencję.
- Zaktualizowano zależności Python usługi `llm_service` oraz wygenerowano ponownie `uv.lock`.
- Bezpośrednie zależności w `llm_service/pyproject.toml` zostały przypięte operatorem `==`: FastAPI `0.139.0`, gRPC i gRPC Tools `1.82.1`, Hugging Face Hub `1.23.0`, PyTorch `2.13.0`, Transformers `5.13.1` oraz Uvicorn `0.51.0`.
- Karencja `uv` dla nowych wydań pakietów została skrócona z 60 do 48 godzin, zgodnie z polityką Bun.

## Container Images

- Publiczny reverse proxy i kontener frontendowy używają `nginx:1.31.2-alpine3.23` zamiast `nginx:1.31.1-alpine`.
- PgBouncer używa `edoburu/pgbouncer:v1.25.2-p0` zamiast `edoburu/pgbouncer:v1.25.1-p0`.
- Etapy pomocnicze PgBouncer i storage używają `busybox:1.38.0-musl` zamiast `busybox:1.37.0-musl`.
- Builder i runtime `llm_service` używają `ghcr.io/astral-sh/uv:0.11.28-python3.13-trixie-slim` zamiast `ghcr.io/astral-sh/uv:0.11.7-python3.13-trixie-slim`.

## Deployment Notes

- Wspierany model wydania `1.0.2` pozostaje oparty na self-hosted Docker Compose.
- Model wdrożenia nadal pozostaje `fresh install only`.
- Głównym publicznym punktem wejścia pozostaje `http://localhost:4567`.
- Aktualizacja nie wprowadza zamierzonej zmiany konfiguracji środowiskowej, API ani schematu bazy danych.
- Ze względu na zmianę bazowych obrazów przed publikacją należy wykonać pełny build i smoke test całego stacka Docker Compose.

Główna dokumentacja deploymentu:

- [docs/infrastructure/deploy.md](../infrastructure/deploy.md)

## Validation Required Before Publication

Backend:

```bash
cd backend
bun run format
bun run lint
bun run typecheck
```

Frontend:

```bash
cd frontend
bun run format
bun run lint
bun run typecheck
bun run build
bun run doctor
```

Infrastruktura:

```bash
docker compose config
docker compose build
```

Po buildzie należy uruchomić cały stack i sprawdzić co najmniej healthchecki, logowanie, obsługę incydentu, upload i download pliku, połączenie przez PgBouncer oraz komunikację backendu z `llm_service`.
